# 用户模型目录与业务绑定

Harness 是模型配置入口，不提供知识库空间切换。新模型保存在当前用户私有配置归属下，已有模型 ID 和归属不迁移。知识库、智能体及任务分别保留自己的选择、默认配置与处理流程。

## 目录与配置权限

`GET /api/v1/models/available` 汇总当前用户有效成员权限内可使用的模型并按 ID 去重，内置模型只出现一次。每条记录的 `can_manage` 由其原归属权限决定，当前业务空间的管理员角色不能用于读取其他来源的连接信息或凭据。租户 API Key 不能调用该用户目录跨越其授权范围，原 `/models` 管理接口保持原归属范围。

编辑知识库时可附加 `knowledge_base_id`，服务端核查该知识库读权限后仅补齐其已绑定模型的脱敏信息。共享知识库授权不开放创建者的整个模型目录。检索与后台处理使用业务资源已绑定的精确模型 ID；仅改变执行租户不会扩大调用者权限。移出共享空间后，知识库授权失败，不能据此检索或取得绑定模型信息。

## 数据与兼容

模型删除会核查所有业务归属下的知识库、智能体和默认设置引用，不返回无权读取的资源名称。PostgreSQL 139 / SQLite 55 添加内部授权策略版本表，不修改已有模型、索引或嵌入维度。首次启用前必须停写并一致备份，核查历史跨归属引用；未经确认的历史引用会阻止启动，不能直接获得新授权。所有新增业务模型引用在数据库写入前按当前用户目录核查，包括未开启的配置项。策略启用后不支持自动执行数据库降级。新建跨业务归属的模型引用需要本版本执行后端；回滚进程前保留当前数据库并核查引用，不能覆盖历史数据以强行降级。

## 验证

`go test ./internal/types ./internal/application/service ./internal/application/repository ./internal/handler/dto -run 'TestUserModelCatalog|TestAvailableModel|TestModelBindings'` 验证同名不同 ID、来源权限、成员撤销、精确资源绑定、执行租户不授予权限、凭据脱敏及跨业务引用保护。平台验收还须分别测试当前用户私有模型、共享知识库检索和撤权后的拒绝访问。
